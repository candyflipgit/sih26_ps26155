# Two-minute demo script

**Before recording:** run `python backend/scripts/reset_demo.py`, start both servers, open
http://localhost:5173, and have the Analyse tab showing. Record at 1440×900 or wider.

The demo has one job: show that the platform handles a vendor it has never seen, *and* that the
security decision is never the model's to make. Everything else is supporting material.

---

### 0:00 – 0:12 · The gap

> "Security frameworks already define what a hardened device looks like. The problem is every vendor
> says it differently — `ip ssh version 2` on Cisco, `protocol-version v2` on Juniper. Hard-coded
> parsers break the moment a new vendor arrives."

*Analyse tab on screen. Click **Cisco Catalyst 9300**.*

### 0:12 – 0:30 · Deterministic spine

*Pipeline stages reveal with their real timings.*

> "Vendor identified, configuration normalised into a vendor-neutral security model, compliance
> evaluated — twelve milliseconds. Serial number, model and OS pulled out for the report."

*Point at the result card: **41%**, CORE-SW-01, serial FCW2447L0GH.*

> "Forty-one percent. And note — one control is *undetermined*, not failed. We never report an
> unparsed setting as a violation."

### 0:30 – 0:52 · Evidence and remediation

*Click **View 13 findings** → click the **Telnet** finding.*

> "Critical: Telnet is enabled. Here's the evidence — and notice there are two lines. One VTY range
> permits Telnet, another doesn't. We resolve toward the risk, because in a security audit missing a
> real exposure is worse than a false alarm."

*Scroll the detail panel.*

> "It maps to CIS, NIST, STIG and ISO from a single catalogue entry. And the fix is the actual Cisco
> command sequence — from a curated template library, never generated by a model. A hallucinated CLI
> command in a security report gets pasted into production."

### 0:52 – 1:10 · The vendor nobody wrote a parser for

*Analyse tab → click **MikroTik RB4011** (badged "no parser exists").*

> "Now the real test. MikroTik RouterOS — we have no parser for this, deliberately. Vendor: unknown.
> Score: zero. Every control undetermined."

*Let that sit for a beat.*

> "A hard-coded tool stops here. This is where ours starts working."

### 1:10 – 1:35 · Teach it once

*Click **Teach AI**.*

> "Fifteen security-relevant commands it couldn't interpret. The model reads each one and proposes a
> mapping with its confidence and reasoning — a proposal, not a decision. Nothing is applied until an
> administrator approves it."

*Select the telnet line. Point at the "Will be learned as" panel.*

> "And look at what gets learned — not the literal string, but the command *shape*. Teach it once and
> every variant is recognised."

*Click **Save mapping**. Repeat for one or two more, quickly.*

### 1:35 – 1:50 · It learned

*Click **Re-scan with 3 new mappings**.*

> "Same file, no restart, no redeployment, no retraining. A critical Telnet exposure that was
> completely invisible sixty seconds ago is now detected — and it's sourced from the knowledge base,
> deterministically. The model isn't in the loop any more."

### 1:50 – 2:00 · The point

*Click **Generate PDF report**, show the PDF briefly.*

> "Device identity, evidence, framework mappings, remediation — with every credential in that
> configuration masked before it was written.
>
> The AI never decided any of this. It interpreted vendor syntax. Rules decided compliance. A human
> approved the new knowledge."

## If asked live

**"What if the model is wrong?"** — It marks the control UNKNOWN, not PASS or FAIL. An AI reading
only counts once a human approves it, and at that point it's a deterministic rule, not a model
output. Wrong AI lowers coverage; it cannot corrupt a verdict.

**"What if the config contains a prompt injection?"** — The config is fenced and labelled as
untrusted data. But the stronger answer is structural: even full compliance with an injected
instruction can't produce a verdict, because the model has no path to one.

**"Why not just embed everything and skip the LLM?"** — We tried. On held-out cross-vendor commands,
correct and incorrect neighbours both scored 0.74–0.80 and retrieval alone got about half right.
Similarity on CLI text isn't separable enough to trust. That measurement is why the LLM is
load-bearing rather than decorative.

**"Does it need internet?"** — No. Point `LLM_BASE_URL` at a local Ollama and the same pipeline runs
on open weights on your own hardware. Nothing leaves the network. And with no endpoint at all, every
part except the suggestions still works.

**"How many vendors?"** — Three ship with parsers, and a fourth is in the demo specifically to show
the path for vendor number fifty. Adding one is a JSON file, not a release.
